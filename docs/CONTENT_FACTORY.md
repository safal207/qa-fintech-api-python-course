# Course Content Factory v0.1

`tools/content_factory` turns one structured Markdown module into a publication-ready course bundle:

- `content-pack.json` — canonical machine-readable package;
- `question-bank.md` — questions with stable IDs and levels L1–L5;
- `api-lab.md` — diagnostic, design, and production-incident API labs;
- `answer-key.md` — reference answers;
- `homework.md` — one complete homework assignment with deliverables and acceptance criteria;
- `assessment-rubric.md` — human-readable 100-point scoring rubric;
- `publication-checklist.md` — structural readiness checks plus explicit manual review gates;
- `quiz.csv` — general question export;
- `assessment-rubric.csv` — tabular scoring rubric;
- `stepik-question-bank.csv` — Stepik test-bank import format.

## Difficulty model

- **L1 Recall** — explain a concept or rule;
- **L2 Apply** — apply the rule through an API check;
- **L3 Diagnose** — connect a symptom to an invariant and user risk;
- **L4 Design** — design a safe contract, retries, state transitions, and observability;
- **L5 Production** — investigate an incident, contain damage, reconcile data, and prove the fix.

Each learning objective produces one question at every level. A module also produces three API labs at L3, L4, and L5.

## Homework and assessment

The generated homework asks the learner to submit:

1. a short test plan;
2. reproducible API checks;
3. pytest coverage for positive and risk scenarios;
4. an evidence package with requests, responses, identifiers, and final state;
5. a concise risk analysis and proposed protection.

The rubric scores the submission out of 100 points:

| Criterion | Points |
|---|---:|
| Contract and test design | 20 |
| Business invariants | 25 |
| Retry, errors, and concurrency | 20 |
| Evidence and reproducibility | 20 |
| Risk analysis and communication | 15 |

The JSON Schema keeps these new `homework`, `rubric`, and `publication_readiness` objects optional, so previously generated v0.1 packages remain valid. New packages always include them.

## Publication readiness

`publication-checklist.md` distinguishes two things:

- **automatic structural readiness** — source references, L1–L5 coverage, L3–L5 labs, answer coverage, homework deliverables, and a 100-point rubric;
- **manual approval** — factual review, Stepik distractor review, sandbox execution, and acceptance of open-ended L4/L5 answers.

`READY` therefore means structurally complete, not automatically approved for release.

## Source module contract

A module must contain:

```markdown
# Module title

Endpoint: POST /payments

## Learning objectives

- objective one
- objective two

## Scenario

A realistic API or production situation.

## Invariants

- business rule that must remain true

## Reference answers

- thesis corresponding to objective one
- thesis corresponding to objective two

## Sources

- docs/COURSE_OUTLINE.md
```

Russian headings are supported as well: `Цели обучения`, `Сценарий`, `Инварианты`, `Эталонные тезисы`, and `Источники`.

## Generate one module bundle

```bash
python -m tools.content_factory.cli \
  --module content/modules/idempotency.md \
  --output generated/idempotency \
  --formats json,markdown,csv,stepik
```

All four format groups are generated by default, so `--formats` may be omitted.

## Build the whole course

Every Markdown file under `content/modules` can be built with one command:

```bash
python -m tools.content_factory.build_all \
  --modules-dir content/modules \
  --output generated/course-content
```

The batch builder:

1. discovers modules recursively in deterministic path order;
2. validates every content pack against `schemas/content-pack.schema.json`;
3. creates an isolated output directory for every module;
4. writes `manifest.json` validated by `schemas/course-content-manifest.schema.json`;
5. exits with a non-zero code when at least one module is structurally `NOT_READY`.

The manifest records stable module IDs, source and content hashes, readiness, question/lab counts, and every generated file. This makes changed modules detectable without mixing their content together.

Generated files are ignored by Git. GitHub Actions rebuilds them from source on every pull request and uploads the complete `course-content-bundles` artifact.

## Stepik export

Stepik's question-bank file import supports test tasks. The exporter therefore converts each generated question into a single-choice task:

```text
text,<question>,-
option,<reference answer>,y
option,<distractor>,n
option,<distractor>,n
```

The file is written as UTF-8 with BOM for convenient spreadsheet review. Review generated distractors before publication; L4 and L5 remain best used as discussion or manually assessed tasks when deeper reasoning is required.

## Validate

```bash
python -m pytest tests/content_factory
```

The tests validate the generated JSON package, backward compatibility with the earlier v0.1 structure, stable IDs, L1–L5 coverage, all publication files, the 100-point rubric, Stepik `text`/`option` rows, deterministic batch builds, and course manifest generation.

## Scope of v0.1

The first version is intentionally deterministic. It does not call an LLM and does not invent factual material outside the source module. Evidence-grounded AI generation may later be added behind the same schema, stable IDs, and tests.
